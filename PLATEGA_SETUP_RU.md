# Подключение Platega в BDAKA SHOP

## Что реализовано

- В карточке товара кнопка «Купить» открывает выбор способа оплаты.
- Существующий внутренний баланс сохранён.
- Platega создаёт отдельный платёж для каждого заказа.
- Заказ считается оплаченным только после проверенного webhook либо серверной проверки статуса через API.
- Проверяются `X-MerchantId`, `X-Secret`, ID транзакции, сумма, валюта и `payload`.
- Повторный webhook не должен повторно выдавать локальный CDK или повторно запускать закупку у поставщика.
- Если Sandromania не вернул код сразу, заказ остаётся в обработке; повторная закупка автоматически не запускается.

## Настройка `.env`

Скопируйте `.env.example` в `.env` и заполните значения самостоятельно. Не отправляйте `.env` в чаты и не добавляйте его в архивы или Git.

```env
PLATEGA_BASE_URL=https://app.platega.io
PLATEGA_MERCHANT_ID=значение_из_кабинета
PLATEGA_SECRET=секрет_из_кабинета
PLATEGA_WEBHOOK_HOST=127.0.0.1
PLATEGA_WEBHOOK_PORT=8080
PLATEGA_WEBHOOK_PATH=/api/payments/platega/webhook
```

Merchant ID и Secret выдаются после подключения магазина. Доступность API и способов оплаты зависит от настроек мерчанта. Настройку финансового кабинета и проверку требований сервиса должен выполнять совершеннолетний владелец/представитель.

## Миграция PostgreSQL

Сделайте резервную копию БД, затем выполните SQL из файла `migrations/005_platega_payments.sql` в базе проекта. `create_all()` не добавляет новые колонки в уже существующие таблицы.

## HTTPS webhook на VPS

Приложение слушает `127.0.0.1:8080`. На VPS настройте reverse proxy (например, Nginx) с действующим TLS-сертификатом и проксированием:

`https://ВАШ-ДОМЕН/api/payments/platega/webhook` → `http://127.0.0.1:8080/api/payments/platega/webhook`

В кабинете Platega укажите этот публичный HTTPS URL в разделе Callback URLs. Сам Telegram-бот продолжает работать через polling; веб-сервер нужен только для входящих уведомлений об оплате.

Проверка доступности локального приложения: `http://127.0.0.1:8080/health`.

## Перед реальными платежами

1. Используйте тестовый товар и минимальную сумму, разрешённую вашим кабинетом.
2. Убедитесь, что callback приходит с правильными заголовками и совпадающими суммой/валютой/payload.
3. Проверьте повторную доставку одного и того же callback.
4. Проверьте сценарии `CANCELED`, `DISPUTED` и `CHARGEBACKED` вручную по тестовым средствам/среде Platega.
5. Не считайте переход покупателя по return URL доказательством оплаты.
6. Проверьте точную схему ответа API в своём кабинете до включения продаж.

Документация: https://docs.platega.io/ — авторизация, создание транзакции, проверка статуса и callbacks.
